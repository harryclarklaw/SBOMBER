Methodology

  • Each component's licence information is read from the SBOM. Concluded licence information is preferred over declared. Where several licence statements are present without an explicit SPDX expression joining them, they are combined conjunctively (AND), which is the conservative reading.
  • Licence identifiers are normalised to SPDX (including resolving deprecated ids), and SPDX expressions are parsed. The expression is then evaluated against the policy: 'A OR B' allows choosing the most permissive option (the best posture wins, as in dual licensing); 'A AND B' requires satisfying every licence (the most restrictive posture wins and obligations accumulate); 'A WITH exception' uses the base licence's posture unless the policy has an explicit rule for the whole expression.
  • Anything that cannot be resolved — NOASSERTION, NONE, a non-SPDX or unrecognised identifier, an unparseable expression, an expression containing any unrecognised identifier, or no licence at all — is assigned the policy's conservative default category and is listed separately. Uncertainty never resolves to 'allowed'.
  • Every classification records the policy rule that produced it, so each result can be audited. The overall posture is the most restrictive posture among all components.
  • Project exceptions are applied after classification. An exception overrides the posture for a named component and version and is recorded, with its justification, owner, and date, in the exceptions section.
  • Output is deterministic: components are ordered worst-posture-first and then alphabetically, and no wall-clock timestamp is included.

Known limitations

  • This tool analyses the component set described by the SBOM only; it is no better than the SBOM it is given. It does not detect missing components.
  • It does not perform linkage analysis (static vs dynamic). This particularly affects weak-copyleft (e.g. LGPL, MPL) assessment, which is therefore surfaced for review.
  • It is not a vulnerability scanner. Vulnerability data, if shown, is taken from the SBOM as-is and is never generated by this tool.
  • It does not assert CRA compliance or any certification. It is a readiness and analysis aid only.
  • Licence resolution covers SPDX identifiers and expressions. Free-text licence names that are not valid SPDX are treated as unresolved rather than guessed.
  • Exceptions match a component name with an exact version (or '*'); version ranges are not supported in this version.
